# MiniNostrApp 设计说明（当前实现，2026-09-30）

> 本文档描述改版**之前**的实现，供后续改动对照。代码位置：`src/`、`index.html`、`build.mjs`、`src/theme.css`。

## 1. 项目定位

MiniNostrApp 是一个极简 Nostr 网页客户端：**纯前端、无后端**，构建产物为静态文件，可部署在任何静态服务器上（当前线上地址 http://lulin.org/client/）。

核心能力四件套：

| 能力 | 说明 |
|---|---|
| 浏览 | 订阅多个 relay 的 kind-1 公开帖子，跨 relay 按事件 ID 去重 |
| 发帖 | 经 NIP-07 浏览器签名器签名后发布 kind-1，私钥不经过页面 |
| 中继管理 | 运行时添加 / 删除 / 开关 relay，显示在线状态，配置存浏览器本地 |
| 详情查看 | 点帖子看事件详情（含 ID 一键复制），点作者看该作者已加载的帖子 |

协议支持：NIP-01（REQ / EVENT / EOSE 的子集，只用 REQ+EVENT）、NIP-07（`window.nostr.getPublicKey` / `signEvent`）、NIP-11（仅 relay 信息页，不直接调用）。

## 3. 数据流架构

```
┌─────────────┐   WebSocket    ┌──────────┐
│ 浏览器页面    │◄──────────────►│ relay × N │
└─────────────┘   REQ kinds:[1] └──────────┘
       │ EVENT(kind-1)
       ▼
  addIncomingEvent()
   - 按事件 id 去重（同一事件多 relay 到达时合并 relays[] 来源列表）
   - 按 created_at 倒序，截断保留最近 MAX_EVENTS = 120 条
       ▼
  React state: events[]
       ▼
  单列信息流渲染
```

**连接管理**（`App` 内 `useEffect`，依赖 `[relays, connectionEpoch]`）：

- relay 配置变更或点"重新连接"（`connectionEpoch+1`）时，500ms 防抖后关闭旧 socket，按 `enabled` 重建连接
- 每个启用的 relay：`new WebSocket(url)` → onopen 发 `["REQ", subId, { kinds: [1], limit: 60 }]`；onmessage 只处理 `EVENT`（kind-1 校验）与 `OK`（发布回执）；onerror/onclose 标 offline
- `relayStates: Record<url, "connecting"|"online"|"offline">` 驱动顶栏信号灯与中继面板状态点

**发布流程**：

1. 点"发帖子"开 composer → `connectSigner()`（无 `window.nostr` 则报错提示安装扩展）
2. `window.nostr.signEvent({kind:1, created_at, tags:[], content})` 本地签名
3. 向所有 OPEN 的 socket 发 `["EVENT", signed]`，本地先行插入事件（relays 记为"本地发布"）
4. `OK` 回执按 eventId 聚合，`publishStatus` 显示 接收/拒绝/等待数

**本地持久化**（localStorage）：

- `nostr-min-relays-v1`：relay 列表 `[{url, enabled}]`；首次加载若缺 `ws://lulin.org` 会自动补入队首（不重置用户已有选择）

```
├── 发帖 sheet（composer-sheet）：textarea（4000 字）＋ 签名发布
├── 帖子详情 sheet（detail-sheet）：作者行 ｜ 全文 ｜ 事件事实表（时间/来源中继/事件ID/作者公钥，均可复制）
└── 作者 sheet（detail-sheet 复用）：大头像首字块 ｜ 完整 npub ｜ 复制按钮 ｜ 该作者已加载帖子列表（点条目跳帖子详情）
```

**内容渲染**（`FormattedNote` + `renderInline`）：

- 按空行分块 → 整块全是 `[-*•]` 行则渲染 `<ul>`，全是 `>` 行则渲染 `<blockquote>`，否则 `<p>`（行内保留 `<br/>`）
- 行内 token：`https?://` 链接（剥离尾部标点，显示 host+path）、`nostr:`/`npub1`… 系列（显示缩短码）、`#tag`（高亮）
- bech32 编码（`encodeNip19("npub"|"note", hex)`）为**自实现**（无外部依赖），`shortKey()` 取 `前8…后6`

**作者身份展示（改版前）**：仅用 pubkey 前 2 个字符做首字头像块 + npub 缩短码，**不拉取 kind-0 profile，不解析 name/about/picture**。

| `--surface-raised` | `#ffffff` | `#151a18` | 弹窗底 |
| `--text` | `#101512` | `#e8eee9` | 正文 |

| `--border` | `#cdd7d0` | `#29322d` | 边框线 |

## 6. 关键常量与边界

| 项 | 值 | 说明 |
|---|---|---|
| `MAX_EVENTS` | 120 | 内存中最多保留帖子数，超量丢弃最旧 |
| 订阅 | `{ kinds: [1], limit: 60 }` | 每 relay 初始拉 60 条 kind-1，不做增量分页 |
| 去重 | 事件 ID | 同一事件多 relay 到达合并 `relays[]`，不重复渲染 |
| 发帖上限 | 4000 字 | composer textarea `maxLength` |
| 默认 relay | 4 个 | `ws://lulin.org`（首选）＋ 3 个日本 wss relay |
| ws:// 支持 | 是 | 允许不加密 relay；HTTPS 页面下浏览器可能拦截，面板如实显示 offline |

## 7. 已知限制（改版前）

1. **无 profile**：不订阅 kind-0，作者只显示公钥缩写，无名字/头像/简介。
2. **无 follow**：没有关注概念，不能关注/取关，全量时间线。
3. **无截断**：长帖子全文渲染，卡片高度不一，信息流节奏碎。
4. **单列布局**：桌面端 720px 单列，大屏留白多。
5. **无增量更新**：只有初始 limit 拉取 + 连接期间的新事件；重连即重新订阅（事件保留在内存 state 中）。
6. **构建耦合**：`build.mjs` 依赖 `@hatch/space-sdk`（Bun 环境），纯 `node` 下 tailwind 插件会报错；类型检查用 `tsc --noEmit`。
